Uygulama dürüst istemci + Cloud Functions varsayımıyla iyi kilitlenmiş (Like callable, entitlement, Rewind match koruması, debug ekranları release’de kapalı). Asıl açıklar Firestore rules’ın callable’lardan daha geniş izin vermesi: değiştirilmiş bir istemci para duvarını ve gizliliği delabilir.

1. Kritik

1.1 Discover get/list tam kullanıcı belgesini verir

firestore.rules (yaklaşık 272–278) · lib/core/services/auth_service.dart

Giriş yapmış herkes discover_eligible == true olan users/{uid} belgesini get edebilir. Alan maskesi yok. Auth aynı belgeye email ve phone_number yazar. Resmi uygulama bunları kartta göstermese de başka bir istemci ham belgeyi alır.

1.2 Who Liked You kurallarla aşılabilir

firestore.rules (yaklaşık 302–304) · swipe collection-group index

Hedef users/{liker}/swipes/{me} okuyabilir. Resonance callable olmadan inbound like listesi çekilebilir. Ücretli özellik rules’ta yok, yalnızca fonksiyonda var.

2. Yüksek

2.1 discover_eligible girdileri istemci yazılabilir

Cloud Function discover_eligible=true yazar (doğru), ama test_completed, assessment_flow_completed, profile_completed, photos, active owner yazabilir. Sahte istemci değerlendirme yapmadan Discover’a girebilir.

2.2 canonical_v1 sahibi tarafından yazılabilir

users/{uid}/profiles/canonical_v1 owner create/update. Production L2 sıralama buna güvenir. 20D vektör sahte üretilebilir.

2.3 User create koruması zayıf; match hâlâ istemci yaratılabilir

Update’te skor/moderation kilitli, create’te değil. matches create, callable’daki canlı-kullanıcı kontrolünü yapmaz.

2.4 Canlı Giphy anahtarı GitHub’da

config/secrets.local.json commit bd05624. .gitignore’da olsa da tracked; history’de kalır. Kota / abuse riski. Firebase client apiKey’leri (firebase_options) client uygulamada normaldir; service account bu repoda görülmedi.

3. Orta — ürün ve kod

3.1 Like sonrası Rewind fail-close

DiscoverScreen._onLike · LikeMatchResult.shouldArmLikeRewind

Rewind yalnızca outcome == no_match ve like_rewindable == true ise kalır. Seed qmatch_stage_b2_seed_10 gibi profillerde backend likeRewindable=false döner; Rewind hedefi silinir; buton disabled; paywall açılmaz. Pass aynı paywall’ı açar çünkü Pass bu bayrağı kullanmaz.

3.2 18+ yalnızca UI

Yaş seçici 18–80. Rules age doğrulamaz. Doğrudan Firestore’a 12 yazılabilir. Who Liked You callable <18 süzer; Discover Firestore path süzmez.

3.3 Profil fotoğrafı her signed-in kullanıcıya açık

storage.rules profile_photos/{userId}/* — belgelenmiş tradeoff. Path bilinirse Discover dışı hesap fotoğrafları da okunur.

3.4 Hesap silme wipe değil

Talep belgesi + Discover’dan soft çıkış. Auth, Storage, mesaj silme operasyona bağlı. account_deletion_requested korumalı alan değil.

4. Düşük

Geçici debugPrint’ler main’de: runtime uid (discover_screen.dart), swipe id listesi (swipe_service.dart), Like outcome. Release’de çoğu kesilir; debug/profile’da sızar.

5. Ne sağlam

  • Like istemci yazamaz; Admin transaction. Public cevap yalnızca outcome + like_rewindable. Block reason sızmaz.
  • Entitlement istemci yazamaz. Satın alma iddiası grant etmez (clientClaimsCanGrant false).
  • Rewind Resonance ister; Like rewind match/thread varsa reddeder.
  • FCM token client R/W kapalı.
  • Debug/admin yalnızca kDebugMode + owner email. Release’de yok.
  • Assessment route gate hata olunca fail-closed. Production L2 ranking trusted callable.

  1. Reverse-swipe okumasını kapat; Who Liked You yalnızca callable.
  2. Public profil / Discover kartını callable yap; email ve telefon Discover get’te olmasın.
  3. Assessment bitiş bayrakları + canonical_v1 yazımını Admin’e al; user create’te protected key’leri kilitle.
  4. Giphy key rotate et; debug print’leri sil.
  5. Persist edilmiş Like’ta Rewind’ı like_rewindable yüzünden körleme; seed’leri production Discover’dan çıkar.
